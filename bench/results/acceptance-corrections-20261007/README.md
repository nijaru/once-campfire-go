# Application contract and media corrections

These checks compare the port with local pinned Rust `64f8635` and Rails `90b3300`. No upstream
source, PR or network Git action was used. This record makes no performance claim.

## Application fixes

- Direct-room settings retain deactivated and banned participants. Memberships, rather than the
  active-user listing, own the participant list; self-pings still display their sole participant.
- Involvement routes render the application document or requested frame. The profile keeps its
  embedded partial rather than nesting another document.
- Missing, empty and whitespace involvement values clear the nullable column. Go's getter reads
  SQL NULL safely; the reference can fail on a subsequent request after accepting the clear.
- Join pages, member account settings and room invitations use versioned account-logo URLs.
  Replacement and deletion change those URLs inside the old image's five-minute freshness window.
  The existing transaction already touches account freshness; no new cache or invalidation layer
  was needed.

The retained HTTP baseline shows Rust passing and Go failing the two new paired view workflows.
Focused tests fail before the fixes and pass afterward. The logo regression uses actual HTTP
multipart replacement/deletion, checks rendered URLs in all three affected templates, and verifies
changed image bytes and restoration of the default logo. It requires no browser.

The final report has 15 workflows and **30 passing implementation runs**. Each uses an isolated
SQLite backup and storage copy. Native CGO `bin/check`, Linux CGO vet/full race tests with
`sqlite_fts5`, and the WebSocket fork's race suite pass. The four new focused web regressions also
pass 20 race-enabled repetitions. Compressed reports and logs are retained alongside this file.

## Required media outputs

The unchanged video-preview golden is 11,788 bytes, MD5 `untJ1VKBeYvbPA/dvRXh9A==`, SHA-256
`57f272b82b06593ab72d04dc1c1108558c9981f271bf3574016c3bb55751d6e2`.
Stock Debian ARM64 FFmpeg `7:7.1.5-0+deb13u1` produces 11,790 bytes from the same fixture and
arguments. Stock AMD64 FFmpeg of that exact package version reproduces the original golden.
Architecture was missing from the version-prefix comparison.

Both Go and Rust pass all **19 original/processed blob comparisons** against the unchanged vectors
using AMD64 FFmpeg with ARM64 libvips 8.16.1. This was a mixed-architecture verification environment
under OrbStack, not a full AMD64 container or a performance comparison. Both also pass all 19
comparisons against a separate native ARM64 Rails capture generated by the unchanged pinned Rails
script. Go checks exact bytes, filename, MIME, service, size, checksum and parsed metadata; the Rust
pipeline checks size, checksum and metadata. No encoder flags, checked-in vectors or expectations
were changed. The original generator's full image identity remains unrecorded.

The strict Go test now checks originals as well as derivatives and reports every derivative in its
own subtest. `CAMPFIRE_STORAGE_VECTORS` selects an explicit alternate capture, matching the existing
Rust facility; default verification still uses the checked-in vectors. The prior description of
this acceptance requirement as optional was incorrect. The `media_vectors` tag isolates external
toolchain requirements, not optional correctness.

Official Debian AMD64 packages were downloaded and extracted privately; host tools were not
replaced. The retained wrapper, package manifest, fixture/vector/output hashes and logs identify
the verification inputs. With the extracted root mounted at `/cache`, the original Go gate was:

```sh
PATH=/cache/parity-acceptance/amd64-bin:$PATH \
  go test -race -count=1 -v -tags sqlite_fts5,media_vectors \
  ./internal/storage -run TestMediaOutputBytes
```

Native ARM64 verification instead sets `CAMPFIRE_STORAGE_VECTORS` to the separate Rails capture
and leaves FFmpeg on the native PATH. Rust uses its existing required-vector integration test.

## Scope and cleanup

The uncommitted screen-harness expansion and rejected WebKit transport workaround were removed.
Previously captured screens are supplementary observations, not the acceptance criterion. Strict
HTML/network equality is not claimed; independent validators, serialization and some titles remain
different. Deleted-room typing suppression and the two-await Turbo cancellation fix remain
intentional safety/correctness differences. Browser proxy diagnostics do not establish a Campfire
application defect, and broader browser sweeps are not required for direct server comparisons.

These checks support the changed application contracts. They do not prove every malformed input,
crash schedule, browser combination or external push provider.
